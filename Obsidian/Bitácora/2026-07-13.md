# Bitácora — 2026-07-13

## Consolidación de skills de Claude Code + 2 skills operativos nuevos

Contexto: revisión de los 18 skills de `.claude/skills/` y 13 comandos de
`.claude/commands/`. Diagnóstico: cobertura suficiente pero con meta-skills
solapados y contradictorios entre sí, y sin skill para las dos operaciones
manuales más recurrentes del último mes (revisión/promoción de calibración y
evaluación CLV/shadow-exit).

**Eliminados (redundantes o contradictorios):**

- `elite-software-engineer`: workflow genérico exhaustivo que contradecía el
  "Control de costos" de `CLAUDE.md` y duplicaba coding-standards.
- `low-cost-mode`: duplicaba íntegramente el "Control de costos" permanente
  de `CLAUDE.md`.
- `settle-bets` (34 palabras, casi vacío): absorbido en `daily-operations`
  como sección de liquidación (SETTLE_ALL → settle_all.py, stale voids,
  auditoría acumulada, idempotencia).
- Comando `/full-system-audit`: fusionado en el skill `full-audit` como
  "Modo orquestado" (roster de 12 especialistas + salida consolidada).

**Acotados (triggers que se pisaban):**

- `sports-analytical-system`: ya NO se activa por análisis de un deporte
  concreto ("picks de béisbol") — eso lo cubren los `quant-*`, que conocen
  adapters y estado de calibración de la plataforma. Queda solo para
  análisis multi-rol explícito (tipster/handicapper/trader/arbitrajista/
  inversor), arbitraje entre books y bankroll conversacional.
- `sports-quant-platform-architect`: queda solo para decisiones de
  arquitectura/diseño (capas, límites de módulos, providers); ya no se
  activa por cambios de código rutinarios.

**Nuevos:**

- `review-calibration`: codifica el flujo train ≠ promote
  (`train_calibration.py` → staging, `promote_calibration.py` dry-run →
  decisión humana con criterios: mejora ECE/Brier OOS, preview no
  degenerado — lección del incidente isotónico 2026-06-30 —, n de
  validación). Ver [[Conocimiento/Calibración]].
- `clv-shadow-exit`: codifica la evaluación CLV repetible
  (`clv_analysis.py`/`daily_clv`, frescura ≤90 min, gate default-deny
  min_n=30, salida shadow = n≥100 y mediana>0) para que cada revisión use
  los mismos umbrales y no se relajen para forzar una salida. Ver
  [[Conocimiento/CLV y selección adversa]].

Resultado: 17 skills (antes 18) y 12 comandos (antes 13), sin triggers en
conflicto. Commit: este mismo (skills + bóveda juntos).
