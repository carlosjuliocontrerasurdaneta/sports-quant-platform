# Bitácora — 2026-07-16

## Dashboard automático al terminar el proceso diario

Pedido de Carlos: que el dashboard (`data/predictions/report_latest.html`)
se abra solo en el navegador cuando corre el proceso diario. El gate por
`SESSIONNAME` del 13-jul evitaba el crash `0xC000013A` bajo el Programador
de tareas, pero dejaba la ejecución de producción (tarea de las 11:00) SIN
apertura automática: el dashboard solo abría en corridas manuales.

Solución — apertura desacoplada en una tarea interactiva:

- **`scripts/open_dashboard.ps1`** (nuevo): abre el reporte en el navegador.
  Sin `-Force` solo abre si el reporte es de HOY y no se mostró aún hoy
  (marcador `logs/dashboard_shown_YYYYMMDD.flag`, autolimpieza >7 días);
  con `-Force` abre siempre (ruta manual).
- **`scripts/register_dashboard_task.ps1`** (nuevo, idempotente): registra
  `SQP_Dashboard_Cdev` en el Programador — tarea INTERACTIVA (LogonType
  Interactive, corre en la sesión del usuario, sin `0xC000013A`) con trigger
  "al iniciar sesión" (delay 1 min) como respaldo si el run de las 11:00
  ocurre sin nadie logueado. Registrada en esta máquina.
- **`DIARIO_COMPLETO.bat`**: al terminar OK, si hay sesión interactiva llama
  `open_dashboard.ps1 -Force`; si corre bajo el Programador dispara
  `schtasks /Run /TN SQP_Dashboard_Cdev` (fallo no fatal: el trigger de
  logon cubre el caso).

Verificación: primera corrida del script abrió el navegador y escribió el
marcador; segunda corrida se omitió por marcador; `schtasks /Run` de la
tarea terminó con `LastTaskResult 0` (y respetó el dedup). Flujo completo
DIARIO → tarea interactiva → navegador queda cableado para el run de mañana
11:00.
